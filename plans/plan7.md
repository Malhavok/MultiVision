# MultiVision Plan7: realtime overlay runtime and spatial anchors

Source: `docs/ADR-0004_ Realtime Overlay Runtime and Spatial Anchors.md`, constrained by the accepted ADR-0001/0002/0003 and Plan6 contracts, the existing session-owned camera runtime, metric calibration authority and Plan5 overlay boundary. This is one complete implementation plan for ADR-0004 for installed `pi-harness 0.3.0` Runtime v3. Do not modify ADR-0001, ADR-0002, ADR-0003, the Plan6 contract, or `harness.toml`. Do not add a validation-contract sidecar: the shared observables needed by every task are compiled below.

## Accepted decisions and shared contract

- Preserve the persistent camera-handle ownership, session slot identity, native camera/projector coordinate model, shared metric calibration, Plan3 diagnostic areas, Plan4 metric ruler, Plan5 generic overlays, Plan6 tag inspection, thin API/CLI boundary and game-agnostic scope. Existing routes and schemas remain compatible unless this plan explicitly extends them.
- Persist `fiducial_groups` as a JSON object keyed by a non-empty namespace. Each value is an object containing exactly the required semantic fields `dictionary` and positive finite `marker_size_mm` (unknown fields are rejected). Dictionary names use the existing canonical detector validation. There is no default group, no default dictionary/size for a group, and no ID-only fallback. A fiducial identity is always `(group, id)`; the same numeric ID in two groups is distinct. An empty group map is valid and means no configured fiducial namespace.
- Add bounded startup configuration for tracking and presentation using the existing JSON configuration conventions: `fiducial_history_length` is a positive integer defaulting to `8` and capped at `32`; `fiducial_tracking_rate_hz` is a finite rate defaulting to `30.0` and bounded to `1.0..60.0`; `fiducial_grace_period_seconds` defaults to the user-approved `5.0` seconds, is bounded to `0.1..60.0` seconds when overridden, and is never shortened by a frame-rate or preview setting; and `fiducial_protection_margin_mm` is a positive finite physical margin bounded to `0.1..1000.0` mm with a documented safe default of `5.0` mm. `max_batch_operations` is a positive integer defaulting to `100` and capped at `1000`. Add `preview_mode` with only `active`, `low_rate` and `off`, default `active`, plus a positive diagnostic `preview_low_rate_hz` defaulting to `10.0` and bounded to `1.0..15.0`. Preview settings are read at process startup only; there is no runtime/API/CLI preview-mode mutation route.
- A configured group's detector runs against retained frames through the existing injectable detector factory/cache. Every usable detection is tagged with its namespace, retains ordered corners and is transformed through the existing camera→projector and, when required, metric projector↔surface authorities. No 3D reconstruction, prediction, Kalman filter, temporal averaging or second transform authority is introduced.
- `SpatialState` is an immutable/copy-on-write snapshot. It contains the current usable calibration authority metadata, selected observations keyed by `(group, id)`, freshness/last-seen metadata, projector footprints and protection regions. Per `(group, id, camera-slot)` history is bounded to the configured history length. The stability score is the arithmetic mean of Euclidean displacement in `surface_mm` between consecutive centres in the retained recent history; a candidate with fewer than two samples has an infinite score, but if every current candidate is unwarmed, select the deterministic fallback by most recent received monotonic timestamp, then lowest stable session slot ID, then highest frame counter. For each identity with at least one warmed candidate choose the usable candidate with the lowest score, then break ties by most recent received monotonic timestamp, then lowest stable session slot ID, then highest frame counter. Camera capture timestamps remain diagnostic metadata and do not participate in expiry when their clock can jump. Use injected monotonic time in tests. A current usable observation wins over a retained grace observation; dynamic spatial candidates require usable metric calibration because stability is measured in `surface_mm`. When all current observations disappear, retain the last selected pose without prediction for the configured five-second default grace period from its last usable observation, then mark it unresolved/hidden. A newly usable observation resolves the same stored overlay automatically.
- An anchor is explicit JSON with `type: "surface"`, `type: "projector"` or `type: "fiducial"`; fiducial anchors carry `group`, `id`, optional metric `local_offset` and `follow_rotation`, while surface/projector anchors carry their explicit coordinates and units. Existing Plan5 `projector_px`, `camera_px` and `surface_mm` point references remain supported for compatibility. Centre/origin/position-bearing overlay requests may consume an anchor; `follow_rotation` composes marker orientation into orientation-bearing geometry, while a metric local offset or rotation-following anchor requires usable metric calibration. Marker-local offset is applied in the marker's surface-mm frame and transformed through the existing metric authority. Invalid/unknown groups, IDs, offsets, missing required calibration, non-finite values and unusable observations fail closed; temporary absence is runtime unresolved state, not an API validation error.
- Add `arrow` as a declarative overlay request with `start`, `end`, style, bounded positive `head_length` and `head_width` in the declared geometry space, and optional label. Build it from one shaft segment plus one triangle head after independently resolving the two anchors. Surface/projector/fiducial combinations, including different fiducial groups, are supported; existing camera anchors remain compatible. Zero-length resolved arrows are rejected/suppressed explicitly without NaN geometry. Physical sizes use millimetres and the existing metric transform, never a pixel-scale shortcut.
- The registry stores immutable declarative requests, not only historical projector coordinates. Listing reports static/dynamic kind, anchor definitions, visibility, current resolved/unresolved state and freshness where useful. Dynamic requests remain stored during marker grace and after expiry. `POST /overlays/batch` accepts ordered `create`, `update` and `remove` operations. Create carries a complete request with its UUID; update carries the target UUID and a complete replacement request with the same UUID; remove carries the target UUID. Operations apply in order to a private candidate registry, including create-then-update/remove within one batch, and the candidate is published once only after the whole batch, all schema/dependency checks and bounded static work succeed. Existing entries, invalid selectors, duplicate IDs, unknown IDs, invalid dynamic specifications, over-limit batches and unsafe geometry reject the whole batch with no registry, render or visibility change. The commit preserves deterministic insertion order for updates and uses one bounded `max_batch_operations` limit.
- Each render frame obtains one immutable complete `RenderSnapshot` containing one registry snapshot, one `SpatialState` snapshot, the active projector descriptor, resolved/materialised generic overlays, legacy point/area/metric layers, calibration/blank-capture suppression flags, global intensity and protected projector regions, plus the camera preview/status snapshot needed by the UI. Resolution/materialisation may happen outside the short publication lock, but the published snapshot must never mix spatial generations, registry generations or projector descriptors; use version checks and a bounded retry or discard a candidate when any authority changes during assembly. The renderer performs no camera reads, fiducial detection, homography, unit conversion, anchor resolution or shape sizing.
- Overlay intensity is bounded to `[0.0, 1.0]`. The service has session-local global overlay intensity, initially `1.0`; each generic overlay style may carry its own intensity, also initially `1.0`. Effective presentation intensity is their product and affects colour/opacity only, never source geometry, clipping dimensions or requested physical size. The global value applies to ordinary projector overlay layers, including legacy point/area/ruler layers; per-overlay style intensity applies to generic entries. Calibration patterns and marker-protection masks are not dimmed by this control.
- For each selected/retained usable fiducial, derive a projector-space marker footprint from its calibrated observed corners and expand it by `fiducial_protection_margin_mm` in surface space when metric calibration is usable, then map it back through the existing metric transform. Without metric calibration, protect the unexpanded calibrated projector footprint rather than inventing pixel scale. Ordinary overlay presentation is clipped/suppressed only inside these regions, without mutating the requested geometry; a crossing line may therefore be discontinuous. Protection is active from an existing usable observation and never waits for marker loss. Calibration-pattern and metric blank-capture exclusivity remains authoritative.
- The realtime target is for a running service: at least 30 accepted and published overlay state mutations per second while capture, tracking, projector rendering and normal preview are active, with no mutation-caused multi-frame projector stall. Measure HTTP/service, validation, mutation/publication, spatial resolution/materialisation, presentation and CPU components separately, and report CLI cold-start latency separately. Do not claim the target from a pure registry microbenchmark or from spawning 30 CLI processes.
- Preserve explicit failure semantics: unknown group, invalid ID, missing/stale calibration, stale observation, non-finite geometry, horizon crossing, projector bounds, zero-length arrow and batch-limit failures are never silently rendered. Temporary marker absence retains intent but suppresses dependent dynamic output after the exact five-second grace period. Board/rectangle detection, game rules, semantic object recognition, persistence across service restart, scene graphs, no-GIL migration, lamp brightness and motion prediction remain out of scope.

## Adversarial safeguards

The implementation must not optimise CLI cold start instead of the running service, fake batching by looping ordinary mutations, materialise away anchor relationships, move vision into the renderer, match fiducials by numeric ID alone, activate protection only after marker loss, retain stale-marker ghosts indefinitely, remove preview as an optimisation, couple projector/API/tracking cadence to preview, migrate to no-GIL without profiling, hold broad locks across detection/materialisation/rendering, delete dynamic intent on temporary loss, alter requested geometry while clipping, overbuild prediction/scene-graph infrastructure, or introduce ADR-0005 rectangle/board detection. Tasks 3–8 and 11–13 contain the corresponding acceptance checks.

## Ordered implementation tasks

1. **Record the ADR-0004 implementation boundary and extend startup configuration.** Add `docs/realtime-overlay-implementation.md` without changing authoritative ADRs, documenting the compound fiducial identity, exact `fiducial_groups` JSON schema, no-default/no-ID-fallback rule, user-approved five-second default grace/recovery, stability selection contract including the unwarmed-candidate fallback, anchor/arrow schema, atomic batch semantics, intensity/protection policy, render-snapshot ownership, preview startup-only modes, realtime benchmark distinction, manual-only hardware claims and all ADR-0004 non-goals. Extend `multivision/config.py` with immutable validated group values, group-map parsing/round-tripping, tracking/history/rate, protection-margin, batch-limit and startup preview fields while preserving unrelated configuration fields and Plan6 `tag_dictionary` behaviour. Add focused configuration tests for defaults, complete round trips, empty groups, invalid names/dictionaries/sizes/rates/margins/limits/modes, unknown fields and atomic save failure. Observable result: `.venv/bin/python -m pytest tests/test_package.py tests/test_config.py` (with the new focused module) passes, and ADR-0001..0003 plus `harness.toml` are byte-unchanged.

2. **Build the group-aware fiducial observation boundary.** Extend the fiducial detection layer with an immutable namespaced observation carrying `(group, id)`, ordered camera/projector/surface geometry, marker size metadata, camera slot/lifecycle generation, frame counter and monotonic freshness. Reuse the existing dictionary validation and detector factory/cache; construct one detector per configured dictionary and never replace the calibration-pattern detector. Run each configured group independently so equal IDs in different dictionaries/namespaces cannot collide, reject unknown groups before detection, retain valid duplicate observations, and omit or explicitly fail malformed detector evidence according to the existing Plan6 boundary. A missing OpenCV dictionary or one group's detector failure must become an explicit group-scoped tracking error/unresolved state without stopping unrelated groups or the capture worker. Add pure tests for dictionary/group isolation, same-ID cross-group coexistence, detector-factory injection, ordered corners, finite geometry, camera/projector/metric conversion and calibration-detector non-interference under skewed homographies. Observable result: the group detector returns deterministic namespaced candidates without opening cameras, mutating overlays or adding a second transform/pose authority, and all existing `tests/test_fiducials.py`, `tests/test_geometry.py` and `tests/test_plan6.py` remain green.

3. **Implement `SpatialState`, bounded history and stable multi-camera selection.** Add `multivision/spatial.py` as the tracker/state owner that consumes retained frames and group candidates, keeps only the configured recent history for each `(group, id, camera slot)`, calculates the specified surface-mm displacement score, selects the most stable current candidate with the exact warmed/unwarmed and timestamp/slot/frame tie-breaks, and publishes immutable snapshots by short atomic swap. Do not publish a dynamic candidate as usable when metric calibration is absent or stale; retain diagnostic detector failures separately. Track camera lifecycle/calibration generations so a closed, unavailable, stale or replaced camera cannot contribute a candidate. Use an injected monotonic clock and deterministic fixtures with two cameras, perspective transforms, equal-ID groups, jitter and tie cases. Test that only the selected stable observation drives an identity, no prediction is performed, malformed/non-finite/horizon-crossing observations are unusable, snapshot readers never see partial marker maps, and a retained last pose becomes unresolved exactly after five seconds and recovers automatically on the next usable observation. Observable result: tracker tests prove stable cross-camera selection, bounded memory, immutable complete snapshots and exact grace boundaries without any renderer/API dependency.

4. **Extend pure overlay anchors and arrow geometry.** In `multivision/overlays.py`, add strict immutable discriminated anchor models and resolution helpers while preserving existing Plan5 point references. Validate namespace, non-negative integer ID, explicit surface/projector coordinates and units, optional finite metric local offset, `follow_rotation`, explicit geometry/units and unknown fields. Extend the centre/origin/position fields needed by rectangle, grid, circle and text requests so dynamic anchors can move them without erasing the declarative request; compose marker orientation only for geometry that has an orientation. Resolve surface/projector/fiducial endpoints independently from one `SpatialState` plus the existing camera/projector and metric authorities; apply marker-local offsets in surface-mm coordinates and follow the observed marker orientation only when requested. Add the first-class arrow request and immutable projector materialisation made of a shaft and triangle head, with positive bounded head dimensions, arbitrary direction, deterministic vertex order and explicit zero-length rejection. Add pure tests for all anchor pair combinations, different groups, missing/grace/unresolved markers, local offset rotation, surface/projector units, arbitrary arrow directions, clipping-ready primitives, non-finite/horizon cases and unchanged declarative requests across repeated resolutions. Observable result: no helper mutates stored requests or computes camera/projector scale, and all existing Plan5 overlay tests still pass.

5. **Replace early-only materialisation with a dynamic specification registry and atomic batch candidate publication.** Extend `multivision/overlays.py`'s `OverlayEntry`/`OverlayRegistry` and the service-owned render-state store in `multivision/application.py` so entries retain normalised declarative requests and can be resolved repeatedly against a supplied immutable `SpatialState`; static overlays continue to behave exactly as before. Implement ordered create/update/remove batch application with one bounded operation limit, complete pre-commit validation, dependency discovery, deterministic insertion/selector rules, candidate snapshot construction and one atomic publish; update keeps identity/order, create collisions and invalid later operations roll back the entire batch, and a valid dynamic request may commit while its marker/calibration is currently unavailable and remains listed while unresolved or hidden; only invalid specification, unsafe static geometry or an exceeded limit rejects the batch. Keep legacy single-overlay routes as compatibility wrappers over the same candidate machinery, and ensure camera/metric/output lifecycle invalidation cannot publish stale materialisations while unrelated projector-only overlays survive. Add service/registry tests for batch ordering, create-update-remove sequences, all-or-nothing failure, limits, concurrent readers, dynamic spec immutability, unresolved listing, dependency invalidation and no intermediate render state. Observable result: a test reader can observe only the old or new committed registry snapshot, never a partial batch, and no camera-management lock is held during expensive geometry generation.

6. **Add presentation intensity and calibrated fiducial protection.** In `multivision/overlays.py`, `multivision/geometry.py` and `multivision/display.py`, implement bounded global/per-overlay intensity normalization and pure per-frame presentation materialisation that applies the effective intensity without changing source geometry or requested dimensions. Build protected projector regions from selected/retained observations, use the existing metric homography for the physical margin when available, use the calibrated footprint without a false pixel-scale margin when metric calibration is unavailable, and clip/suppress ordinary overlay segments/polygons/labels only for the presentation copy. Apply global intensity to generic overlays and existing point/area/ruler layers, but never to calibration patterns or protection masks. Preserve calibration-pattern and metric blank-capture exclusivity and keep protection active before loss. Test perspective-skewed footprints and margins, compound identities, multiple regions, crossing/discontinuous lines, filled/outline shapes, off-screen regions, exact intensity bounds, geometry equality before/after intensity/protection and marker-return recovery. Observable result: stored overlay requests and source-space geometry remain unchanged, protected regions cannot be overwritten by ordinary output in the render snapshot, and the existing projector/metric/point layer semantics remain intact.

7. **Integrate capture/tracking publication and lifecycle invalidation in `MultiVisionService`.** In `multivision/application.py`, add one service-owned tracking worker with a stop event and bounded sleep schedule at `fiducial_tracking_rate_hz`; it reads retained latest frames through a snapshot-only runtime seam without reopening handles, runs every configured group detector, and publishes `SpatialState` independently of preview and projector cadence. Wire startup/shutdown, camera close/open/disconnect, calibration reset/stale transitions, metric reset/recalibration and projector descriptor changes to discard invalid candidates and prevent stale overlay resolution. Expose a single service method that captures one coherent render input and resolves dynamic entries against one spatial snapshot; retain overlay intent through five-second marker loss but fail closed for invalid specifications and missing authorities. Refactor lock boundaries so detection/materialisation/rendering do not run under the broad camera-management lock, while lifecycle transitions remain atomic and late worker results cannot republish after a generation change. Add service integration tests with persistent fake captures, two cameras, injected detectors/clocks, lifecycle races, calibration invalidation, preview-disabled operation, atomic batch publication and legacy Plan3–Plan6 coexistence. Observable result: camera handles remain solely runtime-owned, tracking continues when preview is off, and a complete render input never mixes generations or uses a closed camera.

8. **Refactor display consumption to complete render snapshots and add independent startup preview modes.** Extend `multivision/display.py`, `DisplayServiceLike`, `PygameDisplayRuntime` and `multivision/main.py` so each projector frame consumes one immutable `RenderSnapshot`, draws only service-produced projector-native primitives and protection-safe presentation layers, and never calls camera capture, fiducial detection, homographies, unit conversion or dynamic geometry builders. Preserve main-thread SDL/Pygame ownership, existing layer order, diagnostic areas, metric ruler, point overlay and calibration/blank suppression. Read `preview_mode` and bounded `preview_low_rate_hz` once from startup configuration: active updates preview at its diagnostic cadence, low-rate limits only preview conversion/scaling/blitting, and off performs no preview conversion/blit while capture, retained frames, tracking, calibration validity and dynamic overlays continue. Add fake-Pygame tests for one-snapshot rendering, no partial state, dynamic arrows/overlays, protection masks, intensity, preview active/low-rate/off cadence, lifecycle rebuilds, retryable failures and preserved legacy layer order. Observable result: projector/API/tracking cadence is independent of preview refresh, and the renderer has no vision or spatial authority imports.

9. **Expose the complete ADR-0004 service boundary through strict HTTP API routes.** Extend `multivision/api.py` with `POST /overlays/batch`, `POST /overlays/arrow`, `GET /overlays/intensity`, `PUT /overlays/intensity` accepting `{"intensity": number}`, `PUT /overlays/id/{overlay_id}` for a complete replacement (including per-overlay style intensity), `GET /fiducial-groups` and `GET /spatial-state`, using strict Pydantic request models with explicit anchor discriminators, unknown-field rejection, bounded arrays and JSON-safe normalised responses. Route batch operations to the one service transaction; return structured validation, unresolved-runtime and failure errors without doing detection, homography, clipping, unit conversion or camera work in the API layer. Preserve existing overlay routes as compatibility delegates, expose configured group definitions and selected observation/freshness status without leaking mutable internals or large renderer primitive dumps, and deliberately omit preview-mode mutation routes. Add API tests for create/update/remove ordering, atomic rollback, arrow schemas, cross-group anchors, intensity bounds and effective values, group/state serialization, five-second runtime visibility/recovery, no partial responses, no side effects and all Plan6/Plan5 error/status regressions. Observable result: HTTP can submit a single coherent batch and all new routes delegate to the running service only.
