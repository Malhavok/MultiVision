# MultiVision Plan4: metric surface calibration and physical ruler validation

Source: [ADR-0002: Metric Surface Calibration](../docs/ADR-0002_%20Metric%20Surface%20Calibration.md), constrained by the accepted MVP0 architecture in ADR-0001 and the implemented session-local camera model and diagnostic areas from plans 2 and 3. ADR-0002 is treated as complete planning authority; do not edit ADR-0001, ADR-0002 or ADR-0003. Plan4 ends at shared metric calibration and the minimal validation ruler. It does not implement the generic overlays deferred to ADR-0003.

Shared contracts: [plan4-validation-contract.md](plan4-validation-contract.md).

1. Record the Plan4 implementation boundary in the new implementation-facing document `docs/metric-calibration-implementation.md` without changing any ADR: one session-local shared projector-to-surface-mm calibration, explicit inverse transform, printable A4 target, fail-closed quality/state rules, minimal ruler validation, unchanged per-camera camera/projector calibration, and no ADR-0003 gameplay or generic-overlay work; verify the document and every later task link to the [shared validation contract](plan4-validation-contract.md).
2. Extend `multivision/config.py` with validated metric-calibration thresholds and one authoritative projector-output descriptor/identity used by both camera and metric calibration applicability checks, preserving existing camera-calibration thresholds, non-camera configuration and JSON round trips; verify finite non-negative mm thresholds including the positive RANSAC threshold in mm, ratio/coverage bounds, positive target/version values, malformed configuration rejection and preservation of unrelated configuration fields. See the [shared validation contract](plan4-validation-contract.md).
3. Add `multivision/metric_target.py` with immutable A4 target metadata: portrait 210×297 mm page coordinates, format/version metadata, supported AprilTag family, a deterministic 20-marker 4×5 layout with known surface-mm corners, an unambiguous orientation cue, and a labelled exactly-100-mm reference segment; verify marker IDs/corners are unique and ordered, all geometry is finite and inside the page, the target frame and reference dimensions are deterministic, and the target does not depend on projector pixels, camera resolution or UI layout. See the [shared validation contract](plan4-validation-contract.md).
4. See the [shared validation contract](plan4-validation-contract.md).
5. See the [shared validation contract](plan4-validation-contract.md).
6. Add a strict target-aware fiducial detection/correspondence path in `multivision/fiducials.py` and `multivision/metric.py`, reusing detector seams but not the projector calibration pattern: preserve enough raw detection diagnostics to reject unknown, duplicate, partial, malformed and unreliable markers rather than silently dropping them, associate known target IDs with all four corners, and resolve marker-corner ordering from a provisional spread-marker centre homography so the printed sheet may be rotated without silently permuting physical corners; verify orientation, marker identity, corner order, insufficient coverage and strict detector failures with deterministic fakes. See the [shared validation contract](plan4-validation-contract.md).
7. See the [shared validation contract](plan4-validation-contract.md).
