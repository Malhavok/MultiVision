# MultiVision Plan3: edge-complete calibration and camera available-area diagnostics

Source: the Driver's current Plan3 requirements in this conversation, constrained by the existing Plan2 session model and ADR-0001 geometry/ownership rules. Plan3 adds edge-complete, raster-safe calibration tags and session-local per-camera diagnostic areas with explicit enable/disable control. Areas remain diagnostic-only overlays, while pointing uses the same full native camera-frame footprint subject to projector bounds; no area state is persisted, and ADR-0001 is not edited.

Shared contracts: [plan3-validation-contract.md](plan3-validation-contract.md).

1. Record the Plan3 scope and compatibility boundary in implementation-facing documentation: edge-complete raster-safe calibration tags, session-local per-camera diagnostic areas, explicit enable/disable control, session-local state, full native-frame pointing subject to projector bounds, and no edits to ADR-0001; verify every later task follows the [shared validation contract](plan3-validation-contract.md).
2. Refactor `multivision/pattern.py` marker placement so the default calibration pattern uses a 5×4 grid of 20 tags while retaining the existing explicit 9–12-tag layouts, uses the full configured usable area, places outer tags at maximum raster-safe edge proximity under the existing half-open coordinate rules, preserves marker-size validation and deterministic IDs, and keeps all metadata/rendered pixels inside bounds; verify the generated pattern is deterministic and materially increases edge coverage without clipping. See the [shared validation contract](plan3-validation-contract.md).
3. Add pure `multivision/geometry.py` operations for intersecting a camera polygon with native image bounds, projecting polygon vertices through a homography and clipping the projected polygon to projector bounds, with fail-closed handling for non-finite, horizon-crossing, empty and degenerate results; use the full native camera frame for diagnostic and pointing footprints, and verify identity, perspective, clipping and invalid-transform cases without hardware. See the [shared validation contract](plan3-validation-contract.md).
4. Extend the session camera state in `multivision/session.py` with session-local available-area enablement, keeping the derived polygon owned by the current calibration rather than duplicating geometry state, and preserving deterministic slot ordering; verify default-disabled state, immutable slot identity, rename preservation and serialisation-free lifecycle state. See the [shared validation contract](plan3-validation-contract.md).
5. Add application/service operations that calculate a camera's diagnostic projector footprint from its full native camera bounds and camera-to-projector transform, enable or disable it atomically, and expose current area data without creating a second geometry authority; use the same native-frame footprint for pointing while retaining projector-bound rejection, verify only `OPEN` and `CALIBRATED` cameras can enable an area and failed requests do not mutate calibration, overlays or camera lifecycle state. See the [shared validation contract](plan3-validation-contract.md).
6. Integrate area invalidation with all Plan2 lifecycle boundaries: clear area state before every recalibration attempt and on close, reopen or disconnect, retain it on rename, and require explicit re-enablement after a successful recalibration; verify an old polygon is never rendered during a new calibration attempt or after a failed/invalidating transition. See the [shared validation contract](plan3-validation-contract.md).
7. Extend camera status/list data and the local FastAPI API with `POST /cameras/{slot}/area` accepting `{"enabled": true|false}`, returning slot/name/lifecycle/calibration, enabled state, deterministic colour and ordered projector-native polygon points, with structured errors and idempotent desired-state retries; verify malformed, unknown, unavailable, uncalibrated and invalid-polygon requests leave state unchanged. See the [shared validation contract](plan3-validation-contract.md).
8. Extend `multivision/cli.py` with `multivision cameras area enable <slot>` and `multivision cameras area disable <slot>` against the running service, preserving the thin-client boundary and existing response/error conventions; verify command parsing, URL/payload formation, structured failures and no local camera/Pygame/homography ownership. See the [shared validation contract](plan3-validation-contract.md).
