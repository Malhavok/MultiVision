# MultiVision Plan5: coordinate-aware physical geometry overlays

Source: [ADR-0003: Physical Geometry Overlays](../docs/ADR-0003_%20Physical%20Geometry%20Overlays.md), constrained by the implemented shared metric calibration in Plan4 and the existing camera/projector geometry, session and display contracts. Plan5 adds projector-native and physically calibrated grids, circles, rects, lines and rulers, with camera pixels usable as point references; it does not add game rules, piece tracking, AI logic or a general vector-graphics engine.

The Driver-approved implementation decisions and acceptance observables are recorded in the [shared validation contract](plan5-validation-contract.md). Do not modify ADR-0001, ADR-0002, ADR-0003 or `harness.toml`.

1. Record the reduced Plan5 boundary in `docs/physical-geometry-overlays-implementation.md`: point references are `camera_px`, `projector_px` or `surface_mm`, geometry/measurement spaces are only `projector_px` or `surface_mm`, camera pixels may locate geometry but never define shape size or ruler distance, projector-native geometry remains the final rendering authority, and no game/AI semantics or second scale/transform authority may appear; link the shared validation contract.
2. See the shared validation contract; add bounded overlay configuration plus strict immutable point, quantity, style and request types in `multivision/overlays.py`, with finite values, explicit camera identity for `camera_px`, physical `mm/cm/in` versus pixel `px` units, deterministic angle convention, UUID-backed identity, optional unique names, visibility and fail-closed validation.
3. See the shared validation contract; implement pure point conversion and shape construction using only existing authorities: resolve `projector_px` directly, `camera_px` through that camera's current camera→projector transform, and `surface_mm` through Plan4 metric calibration, convert an anchor into the requested `projector_px` or `surface_mm` geometry space as needed, then build finite circles, rotated rects, explicit-extent square grids, lines and rulers without DPI/local-scale shortcuts or `surface_edge_mm`.
4. See the shared validation contract; implement deterministic projector-output materialisation in `multivision/overlays.py`: bounded circle sampling before projective transformation, four-corner rotated rects, finite explicit-extent grids with exact source-space spacing, mixed-space line endpoints, physical or projector-pixel rulers, strict style normalisation and final projector clipping that never changes requested size or invents boundary strokes.
5. See the shared validation contract; add one session-local `OverlayRegistry` owned by `MultiVisionService` with UUID4 IDs, optional unique names, deterministic insertion order, immutable requests plus materialised projector primitives, list/show/hide/remove/clear operations, no implicit replacement, and explicit camera/metric/output dependency invalidation that removes only affected generic overlays before stale geometry can render.
6. See the shared validation contract; integrate generic overlay create/lifecycle operations with `MultiVisionService` while preserving Plan3 areas, `/overlay/point` and Plan4 metric-ruler compatibility through the existing authorities, keeping projector-only overlays usable without calibration and making failed requests atomic.
7. See the shared validation contract; extend `multivision/display.py`, `PygameDisplayRuntime` and `main.py` with a generic renderer that consumes only immutable service-produced projector primitives, preserves deterministic layer order and legacy point/area behaviour, suppresses ordinary geometry during calibration/blank capture, and never performs coordinate conversion or shape sizing in the UI.
8. See the shared validation contract; add strict thin HTTP routes for grid/circle/rect/line/ruler create plus list/show/hide/remove/clear, return normalized overlay state rather than materialised projector primitives, preserve existing metric/point endpoints, and keep all calibration, geometry, clipping and registry logic inside `MultiVisionService`.
9. See the shared validation contract; add thin CLI commands using validated `--spec-json` creation plus list/show/hide/remove/clear by ID or name, with all runtime operations delegated over HTTP and no local camera, homography, metric, Pygame or geometry authority.
10. See the shared validation contract; add consolidated pure/service/API/display regression coverage for coordinate conversion, mixed camera-anchor plus physical geometry, projector-only geometry, perspective-safe circles/rects/grids, rulers, clipping, styles, budgets, registry lifecycle, dependency invalidation, JSON safety, deterministic rendering and legacy coexistence, using deliberately skewed homographies and no hardware claims.
11. See the shared validation contract; update `docs/mvp0-manual-smoke-check.md` with measured hardware checks for rotated physical grids, circles/rects, lines/rulers, camera-referenced physical geometry, projector-pixel geometry, clipping and lifecycle/invalidation, then run the complete deterministic suite and integration review, removing duplicate scale/transform logic or scope creep and reporting remaining physical uncertainty without modifying ADRs or `harness.toml`.
